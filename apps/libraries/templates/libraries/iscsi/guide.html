iSCSI Export Guide

Learn how to export MHVTL virtual tape libraries over iSCSI

Overview

iSCSI (Internet Small Computer Systems Interface) allows you to export MHVTL virtual tape libraries over the network. This enables backup software running on remote systems to access your virtual tapes as if they were locally attached.

Key Concepts:

  • Target - The server (this system) that exports devices
  • Initiator - The client that connects to the target
  • IQN - iSCSI Qualified Name, a unique identifier (e.g., iqn.2026-01.com.mhvtl:library70)
  • Backstore - The underlying storage device being exported
  • LUN - Logical Unit Number, maps a backstore to a target
  • Portal - Network endpoint (IP:port) where clients connect
  • ACL - Access Control List, controls which initiators can connect

Prerequisites

1

Ensure MHVTL is Running

Your virtual tape library must be started and have SCSI devices available.

# Check MHVTL services $ sudo systemctl status mhvtl # List available SCSI devices $ sudo lsscsi -g [0:0:0:0] mediumx STK L700 0104 /dev/sch0 /dev/sg3 [0:0:1:0] tape IBM ULT3580-TD8 0104 /dev/st0 /dev/sg4 [0:0:2:0] tape IBM ULT3580-TD8 0104 /dev/st1 /dev/sg5
2

Ensure target.service is Running

The LIO target service must be active to export iSCSI targets.

# Check target service status $ sudo systemctl status target # Start if not running $ sudo systemctl start target # Enable for automatic start on boot $ sudo systemctl enable target

Or use the Service Control page in this GUI.

3

Note Your SCSI Device Paths

You'll need the /dev/sg* (SCSI generic) device paths for export. These are shown in the last column of lsscsi -g output.

Tip: For iSCSI export, always use the /dev/sg* devices (SCSI generic), not /dev/st* or /dev/sch*.

Method 1: Quick Export (Recommended)

The Quick Export wizard automates the entire process. Use this if you want to export a complete library with minimal configuration.

1

Go to Quick Export

Navigate to iSCSI Export > Quick Export

2

Select Your Library

Choose the library you want to export from the dropdown list.

3

Select Devices

Check the devices you want to export. Typically this includes:

  • The media changer (robot/picker) - type: mediumx
  • All tape drives - type: tape
4

Configure Access

Choose your access control method:

  • Allow all initiators - Any client can connect (simple but less secure)
  • Specific initiator - Only the specified IQN can connect (more secure)
5

Click Export

The wizard will automatically:

  • Create pscsi backstores for each device
  • Create an iSCSI target with a generated IQN
  • Map all devices as LUNs
  • Configure ACLs and add a default portal
  • Save the configuration
Done! Your library is now available over iSCSI. Skip to the Client Configuration section to connect from a remote system.

Method 2: Manual Step-by-Step Export

Use this method for more control over the configuration, or to understand what's happening behind the scenes.

1

Create Backstores

First, create pscsi backstores for each SCSI device you want to export.

Go to Backstores and click "Create Backstore".

  • Name: A descriptive name (e.g., lib70_changer, lib70_drive0)
  • Device Path: The /dev/sg* path (e.g., /dev/sg3)
  • Plugin: Select pscsi for SCSI passthrough
Important: Create a backstore for the media changer AND each tape drive you want to export.
2

Create an iSCSI Target

Go to Targets > Create Target.

  • IQN: Enter a unique identifier, e.g., iqn.2026-01.com.mhvtl:library70
  • Check "Allow all initiators" for easy setup, or leave unchecked for manual ACL configuration
  • Check "Add default portal" to create a listener on all interfaces (0.0.0.0:3260)
3

Add LUN Mappings

On the target detail page, add LUNs to map your backstores:

  • Click "Add LUN"
  • Select a backstore from the dropdown
  • Optionally specify a LUN ID (or let it auto-assign)
Tip: Add the media changer first (LUN 0), then tape drives (LUN 1, 2, etc.). Some backup software expects this order.
4

Configure Access Control

On the target detail page, configure who can connect:

Option A: Allow All Initiators

  • Check "Allow all initiators (generate_node_acls)"
  • Any client with network access can connect

Option B: Specific Initiators

  • Uncheck "Allow all initiators"
  • Click "Add ACL"
  • Enter the initiator's IQN (find it on the client with cat /etc/iscsi/initiatorname.iscsi)
5

Verify Portal Configuration

Ensure at least one portal exists on the target. If not, add one:

  • Click "Add Portal"
  • IP Address: 0.0.0.0 (all interfaces) or a specific IP
  • Port: 3260 (standard iSCSI port)
6

Save Configuration

Go to Service Control and click "Save Configuration" to persist settings across reboots.

Client Configuration

On the system that will access the virtual tape library (the iSCSI initiator):

1

Install iSCSI Initiator Tools

# RHEL/CentOS/Rocky $ sudo dnf install iscsi-initiator-utils # Debian/Ubuntu $ sudo apt install open-iscsi
2

Start the iSCSI Service

$ sudo systemctl start iscsid $ sudo systemctl enable iscsid
3

Discover Available Targets

Replace TARGET_IP with the IP address of your MHVTL server:

$ sudo iscsiadm -m discovery -t sendtargets -p TARGET_IP:3260 TARGET_IP:3260,1 iqn.2026-01.com.mhvtl:library70
Note: discovery records every target the server offers, and by default the client logs in to all of them at boot. To use one library only, create a record for that target instead: sudo iscsiadm -m node -T <iqn> -p TARGET_IP:3260 -o new
4

Login to the Target

$ sudo iscsiadm -m node -T iqn.2026-01.com.mhvtl:library70 -p TARGET_IP:3260 --login Logging in to [iface: default, target: iqn.2026-01.com.mhvtl:library70, portal: TARGET_IP,3260] Login to [iface: default, target: iqn.2026-01.com.mhvtl:library70, portal: TARGET_IP,3260] successful.
5

Verify Devices Appeared

$ sudo lsscsi -g [3:0:0:0] mediumx STK L700 0104 /dev/sch1 /dev/sg10 [3:0:0:1] tape IBM ULT3580-TD8 0104 /dev/st2 /dev/sg11 [3:0:0:2] tape IBM ULT3580-TD8 0104 /dev/st3 /dev/sg12 # Check the media changer $ sudo mtx -f /dev/sg10 status # the changer's generic node
6

Configure Automatic Login (Optional)

To automatically reconnect after reboot:

$ sudo iscsiadm -m node -T iqn.2026-01.com.mhvtl:library70 -p TARGET_IP:3260 -o update -n node.startup -v automatic
Success! Your backup software can now use the changer's /dev/sg* node (or its /dev/tape/by-id/*-changer link) and the /dev/nst* tape drives. Avoid /dev/sch*: the kernel ch driver leaks references on some changers (see the ch driver leak guide).

Troubleshooting

Discovery fails or times out

  • Check that target.service is running: systemctl status target
  • Verify firewall allows port 3260: firewall-cmd --add-port=3260/tcp --permanent
  • Confirm a portal exists on the target

Login fails with "permission denied"

  • Check ACL configuration - either enable "Allow all initiators" or add the client's IQN
  • Find client IQN with: cat /etc/iscsi/initiatorname.iscsi

Devices don't appear after login

  • Check that LUNs are configured on the target
  • Verify backstores point to valid devices
  • Try rescanning: iscsiadm -m session --rescan

Configuration lost after reboot

  • Save configuration: Go to Service Control > "Save Configuration"
  • Or run: sudo targetcli saveconfig

Logout from target

$ sudo iscsiadm -m node -T iqn.2026-01.com.mhvtl:library70 -p TARGET_IP:3260 --logout
