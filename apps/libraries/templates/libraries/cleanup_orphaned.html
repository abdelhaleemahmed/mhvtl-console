Reconcile the database with device.conf

/etc/mhvtl/device.conf is the authority and the database is a view of it. A full scan reads the files and makes the database match: rows are created for libraries it declares, corrected where the details have changed, reactivated if they came back, and deactivated where it no longer declares them.

Nothing is written to device.conf. The flow is one way. A library absent from the file is meant to be absent from the database, so deactivating its row is the point of this, not a risk of it.

How This Works
  • MHVTL Config: Libraries defined in /etc/mhvtl/device.conf
  • Database: Libraries stored in Django's database for the web UI
  • Orphaned: Libraries in the database that no longer exist in MHVTL config
  • Cleanup: Removes orphaned entries from the database (does not affect MHVTL files)
